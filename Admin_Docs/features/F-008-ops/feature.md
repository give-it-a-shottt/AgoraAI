- 백엔드: services/today.py(오늘 토론 있으면 그대로 → 주제 목록 TODAY_TOPICS 중 아직 없는 주제로 생성 → 다 썼으면 한 번도 안 걸린 완료 토론 중 예측이 가장 많은 것을 올림. 실패하거나 고를 것이 없으면 하루 자리를 돌려줘 같은 날 다시 부를 수 있음), routers/cron.py(비밀값이 비었으면 503, 다르면 401, compare_digest, 응답 TodayCronOut — source: existing·pool·promoted·in_progress·none), main.py 등록, tests/test_cron.py(12)

- 프론트: 무대(pages/StagePage.tsx) — 폴링 중 인터넷이 끊기면 다음 발언을 기다리는 자리에 COM_01_002, 받은 발언·보던 위치는 그대로, 폴링이 계속 돌아 연결되면 저절로 이어짐. 홈 첫 화면 실패도 공통 LoadError로(끊김이면 COM_01_002, 그 밖은 일반 오류, 홈에서는 [홈으로] 없음). 테스트 StagePage 2·HomePage 2

## 면접 예상 질문
1. Vercel Cron 엔드포인트를 아무나 부르지 못하게 어떻게 막았나?
2. cron이 재시도로 두 번 오면 오늘의 토론이 두 개 생기지 않나?
3. 무대를 보다가 인터넷이 끊기면 어떻게 되나?
- 답: (AI 대리 작성 — 사용자 위임) 1) Vercel은 CRON_SECRET을 `Authorization: Bearer` 헤더로 붙여 보낸다. 서버는 secrets.compare_digest로 비교하고, 비밀값이 비어 있으면 빈 헤더로 통과하지 않게 503으로 막는다. 운영에서는 CRON_SECRET이 없으면 서버가 아예 뜨지 않는다. 2) 하루 사용량 칸(daily_usage)에 "cron:today" 자리를 한도 1로 잡는다. UPDATE 한 문장으로 잡으니 두 번째 호출은 자리를 못 잡고 아무것도 만들지 않는다. 3) 이미 받은 발언은 지우지 않고, 다음 발언을 기다리는 자리에만 "인터넷 연결이 끊겼어요"를 보인다. 폴링이 계속 돌기 때문에 연결이 돌아오면 보던 라운드부터 이어진다.
