## 지적
- [위험] [확실] 같은 사용자의 동시 POST /api/debates가 하루 한도·전체 마감을 넘길 수 있음. COUNT만 하고 잠금이 없는데, 몇 초짜리 AI 확인 뒤에야 INSERT — creation.py create·quota_of·_global_used_today, generation.create_debate — diff·generation.py 읽음 — `UPDATE … SET used=used+1 WHERE used < limit` 카운터로 자리부터 잡고 거절·실패면 돌려주기 (Q-001·Q-002 임시 처리와 관련)
- [위험] [확실] 심판 AI 주제 확인 호출에 횟수 제한 없음. 거절·실패는 토론이 안 생겨 어떤 한도에도 안 잡힘 → 한 사람이 반복 호출로 무료 한도를 바닥낼 수 있음 — creation.create, routers/create.py — throttle 미적용 확인 — 사람당·전체 확인 횟수 상한
- [주의] [추정] APP_ENV=production이 빠지면 dev-login이 열리고 운영 비밀값 검사·Secure 쿠키도 빠짐 — routers/auth.py dev_login, config.is_production — Vercel 환경변수는 못 봄 — VERCEL 환경이면 운영으로 강제하거나 명시 허용일 때만
- [주의] [확실] 세션을 서버에서 끊을 방법이 없음. 로그아웃은 쿠키만 지워 복사된 쿠키가 30일 유효 — services/auth.py make_session·read_session, logout — users.session_version을 쿠키에 서명하고 로그아웃 때 올리기 (Q-016 임시 처리와 관련)
- [제안] [확실] /create 입력 중 글자마다 /api/debates/similar 요청(디바운스 없음) — queries.ts useSimilar — 300ms 디바운스
- [제안] [확실] 사용자 한도 COUNT에 (creator_id, created_at) 복합 인덱스 없음 — models.py — 데이터가 늘면 추가

## 체크 항목별 근거
- XSS → LoginModal·CreatePage·auth.tsx → 텍스트 렌더만, 문제 없음
- 토큰 저장 위치 → 세션 HttpOnly·SameSite=Lax·운영 Secure, sessionStorage엔 주제 초안만 → 문제 없음
- 공개 환경변수 → VITE_ 비밀값 없음 → 문제 없음
- 권한 없는 화면 → 서버 require_user 401 → 문제 없음
- 인증·권한 → deps current_user/require_user → 남의 데이터 경로 없음
- OAuth state/CSRF → start_login/check_state(서명 nonce 10분, compare_digest, 제공자 일치) → 문제 없음
- 오픈 리다이렉트 → safe_next("//"·"\\"·상대경로 거부) → 문제 없음
- 세션 서명 → URLSafeTimedSerializer(salt 분리, max_age), 운영 32자 검증 → 서명 문제 없음, 무효화 없음은 지적 4
- 로그인 CSRF·CORS → 단일 origin CORS + SameSite=Lax + JSON 본문 → 문제 없음, dev-login은 지적 3
- 입력 검증 → CreateDebateIn, clean_topic, Query max_length → 문제 없음
- SQL 인젝션 → SQLAlchemy 바인딩 → 문제 없음
- 프롬프트 인젝션 → prompts.sanitize, check_topic(bool, 사유 100자) → 큰 문제 없음
- 비밀키 하드코딩 → config.py → DEV 기본값은 운영 검증에서 거부
- 에러 응답 내부 정보 → create.py 예외 매핑, callback → 원인 미노출
- 패키지 → itsdangerous 2.2.0, httpx 0.28.1 → 알려진 문제 없음(취약점 DB 미조회)
- 민감 정보 → diff → 없음(이메일 요청·저장 안 함)
- 리렌더링·번들 → AuthContext value 매 렌더 생성(영향 미미) → 문제 없음
