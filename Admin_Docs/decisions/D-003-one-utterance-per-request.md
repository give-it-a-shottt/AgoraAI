# D-003 발언 1개 = 요청 1번, 순번 고유 제약 + 생성 잠금

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과]
무엇을: 서버는 토론을 한 번에 다 만들지 않고, 발언을 하나씩 만들어 바로 DB에 저장한다. 화면은 DB에 쌓인 것만 읽는다.
비유: 드라마를 한 회씩 찍어서 바로 방송국에 넘긴다. 시청자는 넘어온 회차만 본다.
왜: 서버리스 함수 시간 제한 안에 들어가고, 중간에 끊겨도 어디까지 됐는지 남는다(DEB_01_007 "2R까지 완성").

## 개발자 상세
- 출처: agora-design.md §0-6 회의론자 지적, §8 "생성은 서버 작업 하나가 발언 1개씩 만들어 DB에 저장(발언 순번 고유 제약 + 생성 잠금)"
- utterances 테이블에 UNIQUE(debate_id, seq). 같은 순번을 두 번 저장하려 하면 DB가 거절 → 중복 생성 방지.
- debates.lock_until: "이 시각까지 내가 만드는 중" 표시. 조건부 UPDATE로 잡아서 동시에 두 작업이 같은 토론을 만들지 않음. 잠금 값(만료 시각)을 작업이 기억해 두고 자기 값일 때만 푼다. TTL 180초(공급자 40초 × 재생성 2번 + 여유).
- 생성 실패가 이어지면(연속 3번, 실패 사이 2·4초 대기) status=paused → 재시도 요청(POST /api/debates/{id}/retry)이 이어서 만든다. 로그인 없이 누를 수 있어 토론당 3번·멈춘 뒤 60초 대기로 제한한다.
- 예상 못 한 오류도 실패로 센다(안 세면 paused가 되지 않아 재기동만 반복됨).
- 동시에 도는 생성 작업은 4개까지(API와 같은 스레드풀을 쓰므로). 넘치면 다음 재기동 때 이어서.
- 대안: 토론 전체를 한 요청에서 생성 → 1~3분이라 함수 제한 초과, 실패 시 전부 날아감. 기각.
