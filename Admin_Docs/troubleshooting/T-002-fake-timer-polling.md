# T-002 무대 대기 시간(30초·60초) 화면 테스트가 부하에서만 실패

## 한눈에 보기 (코드 몰라도 OK)
무슨 문제였나: 가짜 시계로 30초·60초를 돌리는 무대 테스트가 여러 테스트를 함께 돌릴 때만 가끔(나중엔 매번) 실패했다.
어떻게 해결했나: 대기 시계 훅(useWaitElapsed)을 따로 떼어 단위 테스트로 검증하고, 화면 테스트는 "비활성 + 이유"만 확인하게 나눴다.

## 개발자 상세
- 증상: `생각보다 오래 걸리고 있어요`를 못 찾음 / 테스트 5초 초과. 같은 파일만 돌리면 대체로 통과.
- 원인(추정): 무대는 생성 중에 2.5초마다 목록을 다시 읽는다(TanStack Query refetchInterval). 가짜 시계로 수십 초를 돌리면 폴링·렌더·RTL의 기다림(setTimeout)이 같은 시계를 나눠 쓰며 순서가 섞인다. 훅만 떼어 renderHook으로 돌리면 항상 맞게 동작해 화면 코드 결함이 아니라 테스트 환경 문제로 판단했다.
- 해결: hooks.test.tsx(useWaitElapsed·useAutoAdvance 단위), StagePage.test.tsx는 대기 상태의 비활성·이유만. 실제 화면 확인은 배포 전 E2E에서.
- 재발 방지: 폴링이 도는 화면에서 긴 시간을 가짜 시계로 돌리는 통합 테스트는 피하고, 시간 로직은 훅으로 떼어 단위 테스트한다.
